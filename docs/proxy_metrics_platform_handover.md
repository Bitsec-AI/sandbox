# Proxy Metrics Platform Handover

## Endpoint

Implement the platform endpoint consumed by the validator - use an authenticated validator endpoint. Follow the job_run relationship to check the correct validator is submitting:

```http
POST /api/jobs/runs/{job_run_id}/proxy-summary
```

The validator submits this after `complete_job_run()`. Submission is best effort: validator-side failures are logged and do not block job completion.

## Payload

```json
{
  "job_run_id": "123",
  "generated_at": "2026-06-19T12:00:00Z",
  "stats": [
    {
      "phase": "execution",
      "req_model": "qwen/qwen3.6-35b-a3b",
      "model": "qwen/qwen3.6-35b-a3b-20260415",
      "provider": "openrouter",
      "requests": 8,
      "success": 7,
      "error": 1,
      "llm_requests": 10,
      "llm_success": 7,
      "llm_error": 3,
      "retries": 2,
      "input_tokens": 800,
      "output_tokens": 400,
      "cached_tokens": 120,
      "duration_ms_total": 24000,
      "duration_ms_avg": 3000,
      "duration_ms_max": 8000,
      "status_codes": {
        "200": 7,
        "429": 2,
        "502": 1
      }
    }
  ]
}
```

## Fields

- `job_run_id`: job run ID. This is the only run identifier for proxy telemetry.
- `generated_at`: timestamp generated by the proxy summary endpoint.
- `stats`: flat aggregate rows grouped by `phase`, `req_model`, `model`, and `provider`.

Row fields:

- `phase`: `execution`, `evaluation`, or `unknown`.
- `req_model`: model requested by the agent/scorer.
- `model`: model returned by the LLM provider. If the provider errors or does not return a model, this remains the requested model.
- `provider`: proxy provider, currently `openrouter` or `chutes`. Use the existing platform `Provider` enum for this field; do not create a separate proxy-provider enum.
- `requests`: incoming proxy requests completed for this row.
- `success` / `error`: final proxy outcomes for incoming requests.
- `llm_requests`: outbound LLM attempts, including retries.
- `llm_success` / `llm_error`: outbound LLM attempt outcomes.
- `retries`: outbound LLM attempts where `retry_num > 0`.
- `input_tokens`, `output_tokens`, `cached_tokens`: token counters from provider usage payloads.
- `duration_ms_total`, `duration_ms_avg`, `duration_ms_max`: proxy request duration metrics.
- `status_codes`: outbound LLM status-code counts. Store this as a JSON/JSONB field because keys are dynamic status-code strings.

## Suggested Storage

Store one row per `stats` entry, linked to the job run.

Recommended uniqueness for upsert/idempotency:

```text
job_run_id, phase, req_model, model, provider
```

Suggested column types:

- `job_run_id`: foreign key to job run.
- `phase`: enum or constrained string.
- `req_model`: text.
- `model`: text.
- `provider`: existing platform `Provider` enum.
- metric counters: integer/bigint.
- duration fields: integer/bigint milliseconds.
- `status_codes`: JSON/JSONB.
- `generated_at`: timestamp.

The platform can infer project context from the job run. The proxy payload intentionally does not include project IDs or legacy `job_id`.

## Notes

- The summary endpoint never includes full request logs.
- Full outbound LLM-attempt logs stay in Valkey for now and expire after 40 minutes.
- Missing `x-job-run-id` disables proxy tracking for that request. Other missing metadata is normalized to `unknown` by the proxy.
- Treat the telemetry as advisory metrics, not an authorization boundary.
